# V9.1 鱼群显示修复

后续说明：用户提供的浏览器日志已在 V9.2 确认真正的绘制阻断是鱼材质使用 `patch` 保留字。该错误已修复，见 `SHADER_FIX_V9_2.md`。以下保留 V9.1 当时的启动与图层检查记录，不作为着色器兼容验证。

针对“网页看不到鲤鱼”的反馈，先核对本地 V9 源码与构建均含鱼群，再补齐可复现的启动故障和入口问题。尚未取得用户正在访问的实际页面或浏览器错误信息，因此不能断言该页面的唯一根因。

## 修复内容

1. **首帧有鱼。** V9 的实例数量初始为零，必须收到 Worker 的首份消息才填充；静默挂起时可一直没有鱼。V9.1 在本地生成相同种子的初始状态，独立于 Worker 显示完整鱼群。
2. **异常继续游动。** 处理创建失败、`error`、`messageerror`、`postMessage` 抛错与 2 秒无响应。主线程采用同一模拟器接管最近姿态。超时不依赖游动增量，减少动态效果模式也有效。
3. **明确的水下渲染层。** 只在已有 Refractor 相机开启鱼群图层，主视图与倒影不重复绘制；不再把鱼群根对象长期设置为 `visible=false`。
4. **直接观鲤。** 首页直接进入近景，顶部显示“观鲤 / 观亭”，手机使用近景专用相机位置。仍可用原观景菜单进入月洞门、茶席等全部视角。
5. **启动本版。** 更新文档中过时的 V4 启动包名称与 GLB 说明；不再把旧在线预览放在 README 的主入口。项目包更新并不等于线上部署。

## 验证

`node --test tests/fish-visibility.test.mjs tests/fish.test.mjs tests/garden-craft.test.mjs`：14 项通过。新增的首帧与消息错误检查在修复前失败，修复后通过。

覆盖线程始终无响应、暂停动态时超时接管、消息失败、真实 ArrayBuffer 转移、120 条鱼两分钟避碰，以及实际 Refractor 相机的图层/视锥和嵌套渲染异常恢复。折射相机测试采用替代 renderer，不是浏览器截图或 GPU 像素验证。V9 中已有的 CPU 性能记录和原生预览保留为历史记录，没有重新宣称为本次浏览器验证。

本次构建重新生成 `dist`，源码和构建同属 V9.1。未更新原在线网站，未执行真实浏览器、Mac 或手机性能实测。没有生成或打包 GLB/glTF。

## 打开方式

先停止旧项目，将 `changyi-pavilion-v9.1.zip` 解压到新目录，双击其中的 `Start-Mac.command`，使用这次启动自动打开的页面。看到顶部“观鲤 / 观亭”即可区别于旧版界面；开发者可在控制台查看 `window.__pavilion.version`（`9.1`）和 `window.__pavilion.fishStats()`。

页面支持 `#fish` 与 `#overview` 直接定位。原在线地址不会随项目包下载更新；如果需要线上修复，仍需将本版部署到对应网站。
