# 鱼群架构与验证范围（V10 沿用）

V10 恢复原观亭首页，鱼群模型和游动系统沿用 V9.2；场景雾改为只从主体后方开始的线性距离雾。含该雾分支的生产鱼材质已重新进行 GLSL ES 编译检查，见 `SHADER_AUDIT_V10.json`。

V9.2 根据用户浏览器日志修复鱼材质的 `patch` 保留字编译错误。此前的原生预览改用了桌面 GLSL，不能证明 GLSL ES 兼容；现已保留原始 `#version 300 es`，4 个实际程序完成编译与链接，并以原错误作为负向检查。详见 `SHADER_FIX_V9_2.md`。

目标是在原水景中加入数量较多、姿态连贯且能保持间距的锦鲤，同时限制模拟和绘制开销。鱼体来自程序几何，花色来自固定种子的程序材质；不依赖远程模型或新增图片下载。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `fish-habitat.js` | 岛岸与岸石的保守边界、游动区域和湖底上包络 |
| `fish-simulation.js` | 独立于 Three.js 的固定步长模拟、空间网格、邻域行为、惯性转向和非穿透约束 |
| `fish-worker.js` | 在独立线程推进模拟，返回可转移的状态缓冲区 |
| `fish-school.js` | 合并更新请求、回收缓冲区、插值姿态、选择远近模型、更新两个实例化批次 |
| `fish-geometry.js` | 头身比例、眼睛、鳃线、口须和完整鱼鳍；CPU 参考变形与 GPU 使用同一运动定义 |
| `fish-material.js` | 暖白朱红与金色花纹、鳞片微表面、鳍条、眼睛光泽、速度相关的摆尾和游动法线 |
| `lake.js` | 在已有折射阶段绘制鱼群，保留真实深度信息，恢复嵌套渲染状态 |

## 数据与更新

物理使用 60 Hz 固定步长，而绘制跟随浏览器刷新。每次最多补算 4 步；后台暂停不会导致恢复时大量追帧。角度和尾摆相位使用循环值，插值按最短角距离处理。

Worker 最多只有一个推进请求在途，主线程合并新到的时间增量。当前和上一份状态留给插值，只有已经不再使用的缓冲区才交还 Worker；测试使用真正的可转移 ArrayBuffer，检查传递后的矩阵是否仍然有效。物理暂停时不重复发送空更新。

首份鱼群状态在本地同步生成，首帧不再等待 Worker。消息错误、发送失败或任一请求超过 2 秒未响应时，由同一模拟器在主线程接管，并保留最近位置、朝向和游动相位。超时依据实际时间判断，因此减少动态效果模式也能恢复。已退出的 Worker 迟到消息不会覆盖当前状态。

每条鱼的状态包含位置、朝向、俯仰、摆尾相位、速度、转向率、尺寸和个体索引。鱼体变形交给顶点着色器完成，并同步变形法线。只有活动实例的数据范围上传到 GPU。

## 行为与碰撞

邻域行为组合了保持距离、方向协调和松散聚集，参考 [Craig Reynolds 的 Boids 模型](https://www.red3d.com/cwr/boids/)。空间网格将邻居搜索限制在附近单元，避免每个物理步都进行完整的全群两两搜索。

每条鱼独立选择游动目标，并提前估计与邻居的最近接近位置；趋近时优先改变朝向或减速。推进速度、转向角速度、侧向惯性和深度变化有上限，尾摆随实际速度变化，转向时附加身体弯曲和轻微侧倾。

最后一道约束使用包含整个动态鱼体的球形包围体：经过全部尾摆相位、最大转向与最大胖瘦的顶点检查，鱼鳍和尾部仍在包围体内。两球保持正间距即可给实际鱼体留出更大的距离。这个保守方法会让鱼之间比精确网格碰撞留出更宽的空隙，以换取稳定且很小的计算成本。

岸线边界包住原有不规则岛岸与外围石块；湖底使用原深度公式的保守上包络。约束同时限制水面和底部，因此鱼不会依靠穿过岸石、浮出水面或钻入湖底来解开拥挤。

这是实用的实时模拟，不是水体 CFD、真实鱼肌肉动力学或严格的 ORCA 最优避碰求解器。测试证明给定场景和测试条件下的稳定性，不能扩展成任意鱼数、任意输入或所有设备上的绝对保证。

## 渲染预算

| 项目 | 实现 |
| --- | --- |
| 数量 | 桌面 120 条，手机 96 条 |
| 近景模型 | 每条 4,742 个三角面，共享一份几何 |
| 远景模型 | 每条 1,586 个三角面，共享一份几何 |
| 两档基础几何 | 合计 174,408 字节，不含实例缓冲 |
| 材质 | 一个共享 PBR 材质；花色、速度和相位由实例属性控制 |
| 绘制 | 最多两个批次，只在已有水下折射阶段出现 |
| 新增离屏阶段 | 0；复用原水面的颜色和深度渲染目标 |
| 远近切换 | 10.5 / 12.5 米滞回区间，避免在边界附近反复切换 |
| 细纹 | 鳞片纹理在像素不足时衰减，减轻远处闪烁 |

折射阶段保留鱼的深度，原水面会根据到鱼体的光程计算吸收，并与水面反射混合。鱼群对象分配到渲染层 1，只有折射相机开启该层，主相机和反射相机沿用层 0。鱼群在场景树中保持可见，不再每帧来回改全局 `visible`。仍然最多两次鱼群绘制；异常路径恢复水面、渲染目标、XR 开关与阴影更新状态。

## 已完成的验证

- 120 条鱼连续模拟 120 秒，每个物理步检查鱼间间距、岸界、水面、湖底和最大速度；正常游动没有出现大于 2.5 厘米的单步跳位。
- 检查迎面相遇和两鱼重合后的恢复，数值保持有限，包围体间距恢复为正。
- 30 Hz 与 144 Hz 输入推进到相同时间，固定步长状态一致；长暂停最多补算 4 步。
- 两档几何均无零面积三角面，法线有效，鱼体朝向向外，所有采样摆尾姿态在安全包围体内。
- 真正的 Worker 数据转移与回收测试通过，没有使用已经分离的缓冲区。
- 鱼仅在折射绘制中出现，正常和异常路径均恢复相关状态。
- 新增首帧显示、线程超时、消息错误与发送失败恢复测试；通过实际 Refractor 的相机矩阵、图层和视锥检查鱼群参与折射、排除重复绘制。该相机测试使用替代 renderer，不代表浏览器像素验证。
- 与 V8 的 5 项关键材质、几何与阴影回归合计 14 项测试通过；生产构建成功。
- V9 原生 OpenGL 预览曾将源码转换为桌面 GLSL，因此漏掉 `patch` 保留字；V9.2 已修复这个验证缺口，按完整 GLSL ES 3.00 原文编译、链接 4 个程序，并确认原始错误会被拒绝。没有重新生成旧视频。

本环境中，每组预热 300 步后测量 1,800 步，96 条鱼的模拟平均约 0.26 ms，120 条约 0.37 ms；120 条的 95 分位约 0.53 ms。数据见 `FISH_AUDIT_V9.json`。这些是共享 CPU 中的物理模拟成本，未包含整个网页的 GPU 绘制，也不是手机实测帧率。

原生预览使用实际鱼体、实例姿态与水面着色器，省略建筑和全场景环境；视频是 24 fps 的展示文件，不代表网页运行帧率。本轮没有执行完整网页的真实浏览器录屏、原生 Mac 点击流程或手机性能测量。

## 交付

V9.2 ZIP 包含源码、依赖锁定文件、材质源图、网页构建、V9 历史预览视频与检查记录，排除所有 `.glb` 和 `.gltf` 文件。运行时鱼群由源码构建；原有静态建筑 GLB 导出功能保留，但不包含运行时鱼群，本轮未调用建筑导出流程。
