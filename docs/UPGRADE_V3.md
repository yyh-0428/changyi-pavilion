# 长衣亭第三轮升级：接缝精度与场景导出

对照上一轮 `143608c`；本地分支 `upgrade/export-and-joints`。原公开版本为 `f4d5d45`。本轮针对“GLB 与网页不同、部分构件重叠”修改，仍保留原创建筑比例、匾额、草木分布与手机操作。上一轮记录保存在 `docs/UPGRADE_V2.md`。

## 已处理的构造问题

| 问题 | 修改 |
| --- | --- |
| 刚性小瓦只按中心点贴在曲面上，局部穿入基层或错接 | 每片瓦的全部顶点沿同一屋面曲线采样；真实收分、封闭厚度、纵向搭接间隙；按六个扇区复用几何 |
| 宝顶附近瓦片聚集、瓦当和檐口封边互相压住 | 调整上檐内圈与宝顶底座；瓦当按筒瓦高度和原曲线切线放置；檐口两道封边下移，去除重复短椽 |
| 环梁方块端头在六角转角交叠 | 外环梁、内环梁、额枋和藻井采用完整六角环形实体与抹角连接 |
| 斗拱横向构件相互穿插、栏杆 X 花格中心重叠 | 拱臂、横承托和端部垫块分层坐落；花格斜材在交点裁口，立杆终止于上下横栏之间 |
| 桥板、园路小方块在转弯处重叠 | 以曲线的共同横断面生成实体板，设置明确拼缝；桥尾与园路共用对接断面，去掉重复铺设区 |
| 月洞门开口底部与地面轮廓相交，路缘碰到墙脚 | 改为直接连通底边的开口轮廓，并扩宽底部净空；同步调整门框与门顶两坡盖瓦 |
| 轻纱靠近栏杆和柱身，茶杯开底、杯碟悬空 | 帘幕与系带整体内收；茶杯增加杯底、圈足与口沿，杯碟落到茶桌表面 |
| 薄侧面的 UV 没有面积，色彩压缩可能溢出 | 瓦片和铺石侧面重新分配 UV；扩大瓦色存储范围并防止整数溢出 |

瓦片设计中的排水搭接、榫接接触、柱础与土壤等必要连接仍保留。这是原创艺术模型的几何优化，不是实测建筑复原，也不代表全模型已完成布尔求交或工程结构校核。

## GLB 为什么与网页不同，以及现在如何处理

之前只导出 `model.root`：遗漏地形、水、湖底、相机和场景灯光；实例颜色要求查看器识别 `_COLOR_0`；GPU 帘幕风动没有写入网格。

现在网页按钮和命令行使用同一个 `captureScene / exportScene` 流程：先独立复制当时的几何、材质、实例颜色与变换，再导出。草叶使用当前共享网格，帘幕按同一风动公式烘焙位置和法线；灯笼及点光保持当前姿态。导出期间网页仍可继续更新，后续动画不会改变已经捕获的快照。

两种文件都保留地形、湖底、静态水面、六盏点光、两盏方向光、相机，以及 12 张内嵌图片。网页与 GLB 共用标准法线贴图，代替查看器支持不一的 bump 扩展；导出时补齐切线方向。兼容文件的实例颜色与材质基础颜色相乘后写入标准顶点颜色，量化误差不超过每通道 `0.5 / 255`（线性色彩空间）。

| 导出 | 文件体积 | 适用场景 |
| --- | ---: | --- |
| 轻量场景 `changyi-pavilion.glb` | 27.83 MiB | 支持 GPU 实例化及实例颜色的查看器；保留 66,797 个实例 |
| 兼容场景 `changyi-pavilion-compatible.glb` | 127.47 MiB | 普通索引网格，无必需扩展；适合导入建模软件。导出过程需要更多临时内存 |

兼容文件超过 GitHub 单文件限制，已加入忽略规则，随交付包提供，并可用命令重新生成。日常网页使用程序化模型，不会下载或加载这个大文件。

**导入完整场景后，请选择“当前视角”相机。** 自动框选会把远岸和水面也算进去，亭阁因此显得较小。命令行产物使用夕照、全景相机、`time = 2.3` 的可重复快照；网页下载捕获点击后的当前状态。`--model-only` 可生成不含环境的轻量建筑庭园文件。

水面的两层大波保留导出时刻的形状，但实时反射、折射与深度吸收采用静态 PBR 近似。程序天空、雾、半球/环境照明、ACES 曝光和相机画幅偏移不能原样移植为通用 GLB；相应说明、主题、背景色和曝光记录在元数据中。其他软件需要设置自己的环境光，最终画面仍可能不同。月夜网页导出还会复制当时可见的月亮、星点与灯光。不能承诺所有查看器逐像素一致。

新增曲面有实际成本。法线压缩为归一化 16 位整数、UV 使用半精度、瓦色使用 8 位颜色，并复用屋顶扇区，控制缓冲增长。草丛按原空间分块共用少量可变形顶点，替代对大量实例顶点重复计算风动；导出直接复制同一姿态。新增法线贴图限制为不超过 256×256。模型相较原公开版本仍减少约 51.2% 三角形、55.6% 几何与实例缓冲。

瓦片 9,526、枝干 1,044、桃叶 4,752、花朵 2,210、草丛 57,601、草叶 345,606 均保留。模型边界保持约 27.856 × 9.490 × 42.341 场景单位。实例数下降来自屋顶扇区复用，不是删除瓦片。

`src/style.css`、`src/lake.js`、`vite.config.js` 与原部署工作流完全未变。手机断点、相机位置、取景偏移、手势、像素比、阴影和水面分辨率原样保留。页面仅在原“留存”菜单增加兼容导出选项。

上述统计不含纹理、帧缓冲与浏览器堆，网格数不是实际完整帧 draw calls。没有把资源计数当作 FPS。新增草叶 CPU 更新、标准法线材质与内存压缩的综合影响仍需手机实测，不能保证性能零变化。

## 验证与范围

- 16 项自动测试通过：封闭瓦片和搭接间隙、环梁与桥板体积/面朝向、花格单一交点、月洞门净空、半精度 UV 解码、帘幕姿态烘焙、实例变换/颜色/法线、静态波形、资源预算与确定性等。
- 两种实际 GLB 均由 Three.js GLTFLoader 重新导入，并经 Khronos glTF Validator 校验：**0 错误、0 警告**。
- 两种文件交叉对比 147 个实例采样，每个采样检查三个顶点的位置和颜色；6 幅帘幕的全部位置数据一致。
- 轻量文件有 199 条信息提示，主要因为验证器不理解实例化扩展及其访问器；兼容文件有 3 条信息提示：两个灯光目标空节点、保留原始 1024×320 匾额图片。完整报告在 `docs/*-validation.json`，未屏蔽问题。
- Vite 生产构建通过。主包约 644.7 kB、gzip 174.6 kB，导出模块仍按需加载；保留 Three.js 主包超过 500 kB 的常规提示。
- 使用真实 GLB 的离线软件渲染检查屋檐、栏杆与月洞门接缝；该检查采用简化光照，不是网页截图或 PBR 验收。
- 浏览器预览服务仍缺少请求通道，因此未完成 WebGL 着色器实际编译、浏览器下载交互以及 iOS/Android FPS、内存和耗电测试。没有推送或更新线上页面。
